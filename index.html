Bloom Filter

INTRODUÇÃO

INTRODUÇÃO

Um Bloom Filter é uma estrutura de dados probabilística que analisa se uma informação está num conjunto de dados sem precisar acessar a memória em disco. Eventualmente, a estrutura pode apontar um falso positivo (indicando que um elemento está em um conjunto quando, na verdade, não está). Entretanto, jamais gera um falso negativo. Quanto mais elementos são adicionados a uma Bloom filter, maiores são as chances de um falso positivo.

Ou seja, é possível enviar para o “lado cliente” de um software informação suficiente para reduzir dramaticamente requests inócuos e, por consequência, trafego na rede, acessos a “disco” e alocações desnecessárias em memória. Afinal, antes de fazer uma requisição ao servidor para verificar a “presença” de um dado em um conjunto, bastaria o “lado cliente” consultar, antes, ao filtro, podendo prover feedback muito mais rápido sem onerar o backend.

O segredo para a eficiência dessa estrutura de dados é a utilização de hashes de qualidade que são utilizados para ligar ou desligar bits em um mapa. Sempre que um dado é “incluído” no filtro, os bits correspondentes do hash são ligados.

Em sistemas distribuídos ou que manipulam grandes volumes de dados, a verificação direta em estruturas completas pode ser inviável devido ao custo de memória e tempo. Assim, o Bloom Filter se torna uma alternativa leve para consultas rápidas.

Contexto histórico

Esta estrutura de dados foi concebida por Burton Howard Bloom em 1970 que demanda pouco espaço. Ela é utilizada para testar se um elemento está presente em um conjunto sem necessitar consultar a lista completa de elementos presente nesse conjunto.

O trabalho de Pagh, em 2005 propõe uma estrutura de dados de Bloom Filter teoricamente quase ótima em espaço, usando hashing perfeito para lidar com conjuntos de chaves estáticos. Essa estrutura, porém, não era prática por duas razões.

Primeiro, na época, só existiam algoritmos teóricos de hashing perfeito quase ótimo em espaço. Esse problema foi resolvido com novos desenvolvimentos em funções de hash perfeitas, que requerem aproximadamente 2,6 bits por chave armazenada e podem ser avaliadas em tempo O(1).

Segundo, não era possível representar uma função hash totalmente aleatória sem desperdiçar O(n log n) bits. Esse problema foi resolvido pela técnica split-and-share, proposta em 2007 por Dietzfelbinger e Weidling, tornando possível usar O(n) bits para representar uma função hash totalmente aleatória.

Explicação Técnica

Um filtro de Bloom funciona armazenando o conjunto S como um vetor de bits BS, em que os bits são ativados por um conjunto de funções hash verdadeiramente aleatórias. Ele começa como um vetor de todos os bits 0. Cada elemento xi do conjunto S é hasheado k vezes, e cada hash gera uma posição de bit que é configurada como 1. Para verificar se um elemento y pertence ao conjunto, faz-se o hash dele k vezes e verifica-se se os bits correspondentes estão definidos como 1.

Dada a possibilidade de ocorrência de resultados falsos positivos, o Bloom filter é uma estrutura de dados especialmente adequada para cenários em que os métodos convencionais (não probabilísticos, livres de erros) para responder a testes de membresia demandem uma quantidade impraticável de espaço. Ademais, Bloom sugere o uso dessa estrutura para aplicações em que a grande maioria dos elementos testados não fazem parte do conjunto representado pela estrutura. Define-se tempo de rejeição como o tempo médio dispendido por uma estrutura de dados para decidir que um dado elemento não pertence ao conjunto representado. De fato, o Bloom filter permite diminuir o consumo de espaço sem acrescer o tempo de rejeição, o que ocorre com o custo de resultados falsos positivos e impossibilidade de remoção de elementos da estrutura.

COMPLEXIDADE DE TEMPO

SOBRE

Em qualquer aplicação em que falsos positivos não causem problemas significativos, apenas uma aproximação de S pode ser armazenada em vez de guardar explicitamente o conjunto, fornecendo assim uma representação mais compacta que pode caber na memória. Se cada elemento que não pertence a S for um falso positivo com probabilidade de, no máximo, ǫ, então o número de bits necessários para armazenar a aproximação é aproximadamente n log₂ (1/ǫ), enquanto, para evitar falsos positivos, seria necessário armazenar S em pelo menos n log₂ n bits.

Considere o conjunto S' ⊇ S, que inclui os elementos armazenados, inclusive os falsos positivos. O conjunto S' é escolhido de forma que qualquer elemento que não pertença a S tenha probabilidade de, no máximo, ǫ de pertencer a S'. Um filtro de Bloom (Bloom, 1970) é uma estrutura de dados extremamente compacta e elegante para representar um conjunto S' adequado.

Comparação com estruturas similares

Cuckoo Filter

O Cuckoo filter é proposto como uma alternativa ao Bloom filter tradicional para os cenários em que haja remoção de elementos da estrutura, mas sem que haja necessidade de usar um espaço adicional. Vantagens do cuckoo filter sobre o Bloom filter tradicional e outros filtros que permitem remoções de elementos:

  • Permite adicionar e remover itens dinamicamente;
  • Fornece melhor desempenho de consultas do que o Bloom filter tradicional, mesmo quando está quase cheio (com 95% do espaço utilizado, por exemplo);
  • É mais fácil de implementar do que alternativas como o quotient filter;
  • Usa menos espaço que os Bloom filters em muitas aplicações práticas se a razão de falsos positivos 𝜖 alvo é menor que 3%.

    • Quotient Filter

  • Melhor desempenho poque requer apenas uma consulta de cache em média;
  • também suporta a exclusão, mas não elimina outros dados ao mesmo tempo;
  • Não altera a taxa de falso positivo.

    • Counting Bloom Filter

  • Usa contadores ao invés de bits simples;
  • utiliza mais memória;
  • Mas durante uma remoção, ele pode invalidar um bit que estava sendo utilizado por outro dado.
